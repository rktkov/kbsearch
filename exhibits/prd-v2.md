# PRD: Semantic Search over Documents

**Версия:** 2.0
**Автор:** AI-агент (после уточняющего запроса)
**Статус:** Ready for development

## 1. Обзор

Смысловой поиск по базе знаний: пользователь вводит запрос на естественном языке,
система возвращает релевантные фрагменты документов **с указанием документа и раздела**.

## 2. Цели и критерий успеха

- **Критерий приёмки:** запрос возвращает HTTP 200 и непустой список для непустого индекса.
- **Успех:** пользователь находит нужный фрагмент в top-3 и не задаёт вопрос в поддержку.
- **Метрика:** recall@3 ≥ 0.8 на фиксированном наборе из 12 запросов.

## 3. Пользователи

- Сотрудник, который ищет ответ в документации.
- Новый сотрудник на онбординге.
- Автор документации.

## 4. Non-Goals

В эту версию **не входит**:

- генерация ответа языковой моделью (только поиск фрагментов);
- форматы PDF и DOCX (только Markdown);
- права доступа и разграничение по ролям;
- мультиязычные запросы (корпус и запросы на русском);
- ранжирование по свежести документа;
- корпус больше 10 000 документов.

## 5. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | Загрузка Markdown-документов из каталога |
| FR-2 | Разбиение по заголовкам H1–H3, фрагмент ≤ 700 символов |
| FR-3 | Генерация эмбеддингов и сохранение в векторной базе |
| FR-4 | Поиск по запросу: top-K соседей, дедупликация по документу, выдача top-5 |
| FR-5 | Обновление документа при изменении содержимого |
| FR-6 | Удаление документа вместе со всеми фрагментами и векторами |
| FR-7 | Веб-интерфейс с полем поиска |

## 6. Жизненный цикл данных

| Событие | Поведение |
|---|---|
| Документ добавлен | разбить, эмбеддить, вставить |
| Документ изменён | сравнить хеш; при изменении заменить чанки и векторы в одной транзакции |
| Документ удалён из каталога | удалить документ, чанки и векторы в одной транзакции |
| Сменилась модель эмбеддингов | полная переиндексация, старый индекс не смешивается с новым |

## 7. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | p95 поиска ≤ 300 мс на 965 фрагментах |
| NFR-2 | Индекс — один файл, работа без внешних сервисов (кроме локальной модели) |
| NFR-3 | Полная переиндексация корпуса ≤ 20 минут на ноутбуке |

## 8. API

```
POST /ingest          — проиндексировать каталог
GET  /search?q=...    — поиск
GET  /health          — проверка живости
```

## 9. Технологический стек

- Go 1.22
- SQLite + sqlite-vec
- Ollama, модель bge-m3 (1024)
- net/http, html/template
